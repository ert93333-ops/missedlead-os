# WeCover 개선 기록 — 2026-09-09

이번 변경은 기존 접수·견적 흐름의 오류를 고친 작업입니다. 실제 운영 DB 반영, 배포, GitHub 추가 업로드, 결제 활성화는 하지 않았습니다. 전체 출시 검수는 아직 통과하지 않았습니다.

## 바꾼 것

- 다른 업체가 먼저 견적을 제출해도 내 견적 작성 버튼이 유지됩니다. 서버에서 확인한 업체 ID로 내 견적 여부를 판단합니다.
- 신규 접수와 업체 승인은 허용된 우편번호를 사용합니다. 업종도 정확히 일치해야 합니다. 재승인할 때 기존 도시 단위 지역값을 보존해 기존 작업 접근이 끊기는 문제를 막습니다.
- 서버 시작 시와 매분, 24시간이 지난 요청의 빈 업체 자리를 확인합니다. 처음에 업체를 한 곳도 찾지 못한 요청도 대상입니다.
- 요청 상태 확인과 추가 배정을 하나의 DB 처리로 묶었습니다. 예약이 끝난 요청에 새 업체가 들어오는 경합을 막고 최대 3곳, 자격·안전·데모 구분을 지킵니다.
- 영상 첨부에서 남아 있던 챕터 구조와 MP4 챕터 참조 오류를 제거했습니다. 원래 영상 스트림은 보존합니다. 비공개 제목이 노출되는 현상 자체는 재현되지 않았습니다.
- 자동 배정 실패 시 개인정보가 담길 수 있는 메시지 대신 오류 종류와 DB 오류 코드를 기록합니다.

영상 검사는 PC 부하가 큰 상태에서 기본 5초 제한을 넘었습니다. 같은 코드에 진단용 대기 시간만 바꾼 검사에서는 28/28이 통과했습니다. 영상 생성 명령은 30초로 제한하고, 해당 영상 검사에만 외부 명령 실행 시간을 감당하는 60~90초를 부여했습니다. 검사 조건과 서비스의 ffprobe 10초·FFmpeg 30초 제한은 바꾸지 않았습니다. 나머지 7개 시간 초과 항목의 제한은 변경하지 않았습니다.

실제 서버 검증에는 별도 PostgreSQL 16과 PostgREST 16.2를 사용했습니다. 앱의 실제 서버 진입점·저장소·DB 작업과 모바일 견적 판정 함수를 사용했으며 로그인 제공 부분만 테스트 계정용으로 대체했습니다. 실제 Supabase 로그인·저장소 서비스나 기기 검증을 완료한 결과는 아닙니다.

## 남은 확인

- 전체 서버 검사의 7개 시간 초과를 해소한 뒤 다시 전체 결과를 확인해야 합니다.
- BrowserOS에서 업체 화면을 눌러 최종 동작을 확인해야 합니다.
- 허가가 필요한 작업의 허가 등록·운영자 확인 화면이 아직 없습니다. 결제가 활성화된 이후 해당 작업의 시작 절차에 필요한 별도 화면입니다. DB의 허가 보호 조건은 유지했습니다.
- 실제 운영 반영 전에는 0013, 0014 마이그레이션을 순서대로 적용해야 합니다. 결제는 기존 결정대로 비활성 상태입니다.

## 증거와 정리

원본 실행 자료는 로컬 artifacts/improvement-20260908/에 보관합니다: native-api-proof.json, qa-postgres-verification.json, qa-regression-postgres-verification.json, post-cleanup-verification-summary.json, post-cleanup-full-tests.json, job-log-green.json, cleanup.json.

API·DB 테스트 서버를 모두 종료한 뒤에도 전체 검사에 7개 시간 초과가 남았습니다.

이번 테스트용 API·REST·PostgreSQL을 종료했고 5197, 8787, 56521, 56522 포트가 닫힌 것을 확인했습니다. 재현 자료와 종료된 테스트 DB 파일은 Git에서 제외된 위치에 보관합니다. 원래 Docker 실행 도구가 응답하지 않아 그 안에 처음 만든 테스트 DB는 남겨 두었습니다. 다른 프로젝트의 서버와 원래 업무 데이터는 변경하지 않았습니다.
